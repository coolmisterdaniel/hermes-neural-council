# Spor

Проводит до трёх раундов критики с одним отдельным профилем Hermes. Программа
сохраняет исходную позицию, ответы и возражения и не позволяет сменить гостя.

Файл пакета: [скрипт запуска](scripts/council.py).

## Когда использовать

- Пользователь просит моделям обсудить, поспорить или разобраться вместе.
- Решение дорого переделывать и одного мнения недостаточно.
- Для проверяемого факта сначала проверь источник или запуск; не спорь о том,
  что можно установить напрямую.

## Предварительная настройка

Нужен отдельный профиль Hermes, например `council-1`. Перед сравнением нескольких
слотов предупреди: разные имена профилей могут вести к одной модели.

## Раунд 1

1. Сохрани исходную позицию и материал в один UTF-8 Markdown-файл.
2. Запусти dry-run:

   `python3 ${HERMES_SKILL_DIR}/scripts/council.py spor --profile council-1 --input <файл> --topic <тема> --dry-run`

3. Покажи профиль, стоимость одного вызова и предупреждение о приватности.
4. После подтверждения добавь `--confirm`. Сохрани путь `conversation` из JSON.

## Раунды 2 и 3

1. До изменения исходного материала напиши отдельный файл разбора: точные
   замечания гостя и напротив каждого «принято» либо «оспариваю» с причиной.
2. Запусти dry-run с той же папкой и тем же профилем:

   `python3 ${HERMES_SKILL_DIR}/scripts/council.py spor --profile council-1 --input <разбор.md> --conversation <папка> --dry-run`

3. Получи отдельное подтверждение следующего вызова и повтори с `--confirm`.
4. Третий раунд делай только при оставшемся содержательном разногласии.

## Итог

Запиши два списка: «сошлись» и «остались при своём». Для второго сохрани обе
позиции и отметь рекомендацию ведущего как мнение заинтересованной стороны.

## Ограничения

- Максимум три успешных ответа; четвёртый блокируется программой.
- Профиль нельзя менять внутри разговора.
- Исходный `source.md` нельзя менять между раундами.
- Ошибка и пустой ответ не считаются успешным раундом и не повторяются сами.
- Не добавляй `--confirm` без подтверждения каждого платного вызова.

## Проверка

После каждого успеха JSON содержит номер `round` и файл `response`. В
`state.json` число `successful_rounds` совпадает с количеством файлов ответов.
