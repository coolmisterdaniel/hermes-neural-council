# Consigliere

Провести один глубокий разбор по схеме:

`интервью → сторож → два независимых ресерча → критика → судья`.

Использовать только для решений, которые дорого переигрывать, которые затрагивают
несколько областей и где заранее неизвестно, какие угрозы искать. Для одного
мнения использовать `mini-sovet`; для нескольких раундов с одной моделью — `spor`.

Файлы пакета: [скрипт запуска](scripts/consigliere.py),
[критерии готовности](references/readiness-criteria.md),
[шаблон цели](assets/goal-template.md) и [шаблон брифа](assets/brief-template.md).

## Подготовка профилей

Обязательны два разных профиля Hermes:

- `council-1` — первый ресерч и судья;
- `council-2` — сторож, второй независимый ресерч и, по умолчанию, критик.

Сторож сидит не на профиле судьи: он решает, годится ли задача, по которой тот же
слот иначе выносил бы и приговор.

Необязательный `council-3` делает критику независимее. Разные имена профилей не
доказывают, что внутри разные модели: попросить пользователя проверить настройки.

Пять ролей на два профиля не раскладываются, поэтому оставшиеся совпадения
программа не запрещает, а печатает: поле `role_overlaps` в JSON и примечание в
первых строках вердикта. Это примечание из вердикта не удалять.

## 1. Подготовить рабочую папку

Выполнить:

`python3 ${HERMES_SKILL_DIR}/scripts/consigliere.py --prepare --topic <короткая-тема>`

Сохранить из JSON пути `conversation`, `goal`, `brief` и `criteria`. Все материалы
остаются в приватной папке `$HERMES_HOME/neural-council/`, а не в Git.

## 2. Провести интервью

Прочитать `${HERMES_SKILL_DIR}/references/readiness-criteria.md` полностью.
Задавать пользователю по одному уточняющему вопросу за раз. Не превращать пять
критериев в формальную анкету: если ответ уже известен из разговора, не спрашивать
его повторно; если ответ расплывчатый, уточнить до следующего пункта.

После интервью заполнить подготовленные `goal.md` и `brief.md`:

- не добавлять факты, которых пользователь не сообщал;
- явно отделять факты от предположений;
- сохранять нерешённые вопросы;
- не записывать токены, пароли и другие секреты;
- не включать имена, контакты и другие идентификаторы, если без них можно
  сформулировать задачу.

Показать пользователю короткое содержание цели и брифа. До сторожа прямо сказать,
что оба файла будут отправлены поставщику модели профиля `council-1`; проверка
секретов не является полным обезличиванием. До подтверждения не звать сторожа.

## 3. Проверить готовность

Сначала выполнить сухую проверку:

`python3 ${HERMES_SKILL_DIR}/scripts/consigliere.py --conversation <папка> --profile council-1 --research-profile council-2 --only-guard --dry-run`

Показать профиль и предупредить, что сторож — один вызов модели. После явного
подтверждения повторить без `--dry-run`, добавив `--confirm`.

- `НЕ ГОТОВО`: прочитать вердикт, задать только недостающие вопросы, обновить
  `goal.md`/`brief.md` и повторить этот раздел с новым подтверждением.
- `ГОТОВО`: показать пользователю вывод сторожа и перейти к подтверждению
  полного запуска.

Вердикт сторожа начинается с раздела «Как я понял задачу». Показать этот пересказ
пользователю дословно и спросить, совпадает ли он с замыслом. Расхождение здесь
стоит одной правки брифа, а дальше — четырёх дорогих вызовов по не тому вопросу.

Сторож внутри программы один. Не вызывать отдельного второго сторожа вручную.

## 4. Запустить полный разбор

Сначала выполнить ту же команду полного запуска с `--dry-run` вместо `--confirm`
и показать пользователю список `planned_calls`.

Предупредить: впереди четыре вызова профилей, два из них — глубокие веб-ресерчи;
материал уйдёт поставщикам выбранных моделей и может использовать веб-поиск.
Получить отдельное явное подтверждение всего четырёхэтапного запуска.

Без третьего профиля:

`python3 ${HERMES_SKILL_DIR}/scripts/consigliere.py --conversation <папка> --profile council-1 --research-profile council-2 --confirm`

С независимым критиком добавить `--critic-profile council-3`.

При обрыве повторить ту же команду только после нового подтверждения: готовые
этапы пропустятся, а незавершённый вызов автоматически не повторяется.

## 5. Показать результат

Если в JSON непустой `unanswered_critique` — сказать пользователю прямо: судья не
ответил на эти замечания критика. Вывод показать можно, но приёмку он не прошёл.

Разбор замечаний лежит отдельным файлом `acceptance` и в вердикт не подмешивается:
владельцу — продукт, проверяющему — след.

Прочитать файл `result` из JSON. Показывать пользователю решение судьи как вывод
по проблеме, а не отчёт о работе моделей. Карты и критику сохранять как след для
проверки, но не перегружать ими основной ответ.

Обязательно сказать: согласие моделей не равно истине; важные факты подтверждает
первоисточник или профильный специалист.

## Запреты

- Не добавлять `--confirm` без соответствующего подтверждения пользователя.
- Не запускать полный разбор без сохранённого `ГОТОВО` на неизменных входах.
- Не обходить проверку секретов и не переиспользовать карты после изменения
  цели, брифа, критериев или профилей.
- Не обещать точную стоимость: её определяют выбранные профили и объём ресерча.
- Не добавлять новые этапы, голосование или автоматические повторы.
