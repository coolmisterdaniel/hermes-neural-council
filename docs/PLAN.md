# План реализации Hermes Neural Council

## Версия после собственной критики

1. Зафиксировать публичный договор v0.1.0 в `SPEC.md` и не переносить личные
   пути, карточки моделей или Obsidian-интеграцию.
2. Создать Tap-структуру `skills/mini-sovet` и `skills/spor` с современным
   frontmatter Hermes, понятными условиями запуска и настройкой профиля-слота.
3. Сделать один исходный Python-модуль для обоих режимов. При сборке копировать
   его именно в `scripts/` каждого скилла, чтобы Hermes Tap скачивал код вместе
   с отдельно установленным скиллом, но логика не расходилась.
4. Реализовать неизменяемый журнал разговора: вход, собранный запрос, ответ и
   `state.json`. Для спора хранить исходный материал отдельно от возражений.
5. Реализовать безопасный вызов `hermes --profile <слот> --ignore-rules
   --toolsets safe -z <запрос>` с тайм-аутом, без shell и без повторов.
6. Добавить проверки профиля, числа раундов, размера входа, имён и содержимого
   секретоподобных файлов, пустых ответов и повреждённого состояния.
7. Написать модульные и сквозные тесты с подставной командой Hermes. Проверить
   Mini-sovet, три раунда Spor и все защитные отказы.
8. Добавить README, лицензию, руководство первого запуска и команды установки
   через Hermes Tap.
9. Провести локальную проверку структуры и штатным сканером Hermes на отдельном
   временном `HERMES_HOME`. Если community-сканер выдаёт предупреждение,
   сначала убрать ложные срабатывания. Допустимо оставить только неизбежное
   предупреждение о запуске дочернего процесса Hermes и объяснить его до
   установки; опасный вердикт обходить запрещено.
10. Обновить проектную заметку в Obsidian. Публиковать GitHub-репозиторий только
    после отдельного подтверждения владельца.

## Порядок проверки

- Сначала тесты без моделей.
- Затем `--dry-run` с реальным исполняемым файлом Hermes.
- Затем загрузка локальных папок скиллов во временном `HERMES_HOME`.
- После разрешённой владельцем публикации — настоящая установка из GitHub Tap;
  только она проверяет весь публичный путь распространения и обновления.
- Живой платный вызов не входит в автоматическую проверку и требует отдельного
  решения владельца.
