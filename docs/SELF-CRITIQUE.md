# Собственная критика первоначального плана

## Что было неверно или слабо

1. **Два вручную поддерживаемых скрипта разошлись бы.** Tap устанавливает каждый
   скилл отдельно, поэтому общий файл вне папки скилла не попадёт пользователю.
   Исправление: один исходник плюс проверяемая сборка двух самостоятельных
   пакетов.
2. **Одного `SKILL.md` недостаточно для защит.** Модель может забыть ограничение
   раундов или случайно сменить гостя. Исправление: ограничения закрепляются в
   программе и тестах.
3. **Профиль сам по себе не даёт независимый контекст.** В него могли попасть
   память, правила и инструменты. Исправление: `--ignore-rules` и безопасный
   набор инструментов в каждом гостевом вызове.
4. **Нельзя автоматически повторять ошибочный платный вызов.** Повтор может
   дважды списать лимит и скрыть проблему. Исправление: ошибка сохраняется, но
   повтор делает только пользователь.
5. **Сохранение в текущую папку опасно для публичных проектов.** Разговор может
   случайно попасть в Git. Исправление: приватная папка Hermes по умолчанию.
6. **Передача папки целиком слишком широка.** Она может раскрыть лишние файлы.
   Исправление: только один явно выбранный входной Markdown-файл.
7. **Слоты нельзя объявлять моделями.** Два профиля могут указывать на одну
   модель. Исправление: интерфейс говорит «профиль/слот», а README честно
   предупреждает, что независимость моделей пользователь проверяет сам.
8. **Живой тест нельзя делать частью обычных тестов.** Он требует ключей и тратит
   лимит. Исправление: подставной исполняемый файл и отдельный ручной smoke-test.

## Оставшиеся риски

- Текст запроса передаётся Hermes как аргумент `-z`; на многопользовательской
  машине он может быть кратко виден в списке процессов. Для v0.1 это нужно явно
  описать. Полное устранение потребует стабильного stdin/API-интерфейса Hermes.
- `safe` разрешает веб-инструменты. Это полезно для проверки фактов, но внешний
  поиск может отправить поисковому сервису часть запроса. Пользователь должен
  видеть это предупреждение; позже можно добавить режим без инструментов, если
  Hermes предоставит официальный пустой набор.
- Название профиля не доказывает, какая модель используется. Скрипт может
  гарантировать неизменность профиля в споре, но не внутренней настройки этого
  профиля между раундами.

## Что принято после оценки Claude Opus

- Уточнено, что устанавливаемый код обязан лежать в `scripts/` каждого скилла.
- Tap ограничен публичным GitHub.com; локальная проверка не выдаётся за полную
  проверку публичной установки.
- Добавлен план действий при предупреждении community-сканера.
- Возвращено обязательное предупреждение, если два слота могут вести к одной
  модели.
- Пути в программе должны строиться через `pathlib`, без Unix-хардкода.

Замечание Claude о несуществующем `--toolsets safe` отклонено: в установленном
Hermes этот набор объявлен в `toolsets.py`, проходит штатную валидацию и содержит
веб/vision/image_gen без terminal и file. Одноразовый режим передаёт явно
выбранный набор вместо настроенного набора CLI (`use_config_toolsets=False`).
