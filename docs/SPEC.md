# Спецификация Hermes Neural Council v0.1.0

## Результат

Публичный Hermes Tap с двумя скиллами:

- `mini-sovet` — один независимый ответ выбранного профиля Hermes;
- `spor` — до трёх раундов критики с тем же профилем.

Личный проект `/root/consigliere` не является зависимостью и не меняется.

## Пользовательский сценарий

1. Пользователь добавляет Tap и устанавливает один или оба скилла.
2. Создаёт хотя бы один отдельный профиль Hermes, например `council-1`, и
   выбирает для него любую доступную модель.
3. Просит основной Hermes «дерни модель №1» или запускает `/mini-sovet`.
4. Скилл сохраняет исходный материал, вызывает профиль-гость и сохраняет ответ.
5. Для `spor` каждый следующий раунд автоматически получает исходный материал,
   предыдущий ответ гостя и возражения ведущего.

## Границы первой версии

- Поддерживаются Linux и macOS при наличии `python3` и команды `hermes`.
- Windows отложен до отдельной проверки команды запуска Python в Hermes Desktop.
- Модель выбирается настройкой профиля Hermes, а не именем внутри скилла.
- Слоты — соглашение об именах профилей: `council-1`, `council-2` и далее.
- Названия слотов не доказывают независимость моделей. Перед сравнением двух
  слотов пользователь должен проверить, что они не указывают на одну модель;
  скилл обязан напомнить об этом, но не угадывает настройки профиля.
- Один запуск обращается только к одному гостевому профилю.
- Нет параллельного совета, голосования, автоматического судьи и интеграции с
  Obsidian.
- Нет автоматического повторного платного вызова после ошибки.

## Изоляция гостя

Гостевой Hermes запускается с отдельным профилем, `--ignore-rules` и набором
инструментов `safe`. Он не получает память, `AGENTS.md`, `SOUL.md`, личные
скиллы ведущего, терминал или файловые инструменты.

В гостевой запрос входят только:

- исходный материал;
- правила ответа или честной критики;
- в раундах 2–3: предыдущий ответ гостя и возражения ведущего.

## Хранение

По умолчанию материалы сохраняются вне Git в
`$HERMES_HOME/neural-council/`, а если `HERMES_HOME` не задан — в
`~/.hermes/neural-council/`.

Каждый разговор получает отдельную папку с `state.json`, входными файлами,
собранными запросами и ответами. Секреты в `state.json` не записываются.

## Защиты

- Явно показывать профиль перед вызовом.
- Требовать отдельное подтверждение ведущего перед реальным вызовом.
- Иметь `--dry-run`, который ничего не отправляет модели.
- Не принимать `.env`, ключи, файлы авторизации и приватные ключи.
- Проверять типовые признаки токенов в содержимом.
- Ограничивать размер входа.
- Ограничивать спор тремя успешными ответами.
- Запрещать смену профиля внутри спора.
- Не считать ошибку или пустой ответ успешным раундом.
- Не повторять вызов автоматически.

## Критерии приёмки

1. Структура репозитория распознаётся как Hermes Tap: оба `SKILL.md` лежат под
   `skills/<name>/` и содержат обязательные поля.
2. `${HERMES_SKILL_DIR}` используется для переносимого запуска скрипта.
3. Подставная команда Hermes подтверждает правильный профиль и изоляционные
   флаги без сетевого вызова.
4. `mini-sovet` сохраняет один вопрос, один собранный запрос, один ответ и
   состояние разговора.
5. `spor` сохраняет до трёх ответов, прикладывает предыдущий ответ, не позволяет
   сменить профиль и блокирует четвёртый раунд.
6. Секретоподобный файл и секретоподобное содержимое блокируются до вызова.
7. Сбой, тайм-аут и пустой ответ не увеличивают номер успешного раунда.
8. Все автоматические тесты проходят без API-ключей и без расходов моделей.
9. README объясняет установку через интерфейс Hermes и команды как запасной
   вариант, настройку профилей, стоимость и приватность.
10. Локальный штатный сканер Hermes не классифицирует скиллы как опасные. После
    публикации та же проверка повторяется настоящей установкой из Tap.
